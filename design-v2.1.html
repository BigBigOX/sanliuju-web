1. 状态机重构（P0）

核心问题：当前游戏状态散落在 S.game.roundPhase、S.game.question、S.game._draftQuestion、S._answeredThisRound 等多个字段中，没有一个统一的状态描述。一个操作可能改变多个字段，组合爆炸导致 Bug。

1.1 显式状态机

// 当前：散落字段
S.game.roundPhase   // 'question'|'analysis'|'results'|'penalty'|'settlement'
S.game.question      // null | string
S.game._draftQuestion // null | string
S._answeredThisRound // true | false

// V2.1：单一状态枚举
S.game.phase = 'idle'          // 等待主持人操作
             | 'drafting'      // AI 生成题目中
             | 'preview'       // 主持人预览草稿
             | 'answering'     // 玩家答题中（计时器运行）
             | 'analyzing'     // AI 分析匹配中
             | 'results'       // 展示匹配结果
             | 'voting'        // 惩罚投票中
             | 'settlement'    // 轮次结算
             | 'ended'         // 游戏结束

// 每个阶段有明确的进入/退出动作，按钮和 UI 只问一个字段

1.2 状态转换规则

当前状态触发事件下一状态副作用
idle主持人点"来一题"drafting调 AI 出题
draftingAI 返回题目preview存 _draftQuestion，渲染预览
preview主持人点"发布"answering清 draft，设 question，广播 QUESTION，启计时器
preview主持人点"跳过"idle清 draft
answering全员答完或计时到analyzing停计时器，调 AI 分析
analyzingAI 返回分析results存 heat，广播 MATCH_RESULT
analyzingAI 分析失败results兜底文案，"AI 分析暂不可用"→"默契度已更新"
results检测到惩罚阈值voting生成候选，广播 VOTE_START
results题目数不够idle按钮显示"下一题"
voting投票结束results广播 VOTE_RESULT，触发惩罚揭晓
results题目数够了settlementAI 生成结算，广播 ROUND_SETTLEMENT
settlement主持人点"下一轮"drafting进入下一轮，自动出第一题

1.3 按钮文字由状态决定

idle       → "🎲 来一题"
drafting   → 隐藏（AI 生成中）
preview    → "📤 发布题目"
answering  → 隐藏（计时中）
analyzing  → 隐藏（分析中）
results    → "🎲 下一题"
voting     → 隐藏（投票中）
settlement → 隐藏（结算自动跳转）

2. 答题框消失问题（P0）

根因：renderPlayerBoard 里答题框的可见性条件是 S.game.question && S.game.timerRunning。但在 draft → publish 过渡期间，question 被清空（hostGenerateQuestion 重置为 null），导致渲染时答题框隐藏。 
// V2.1 修复：答题框只在 answering 阶段显示
if (S.game.phase === 'answering') {
    answerArea.style.display = ''
    if (S._answeredThisRound) { /* 已答状态 */ }
    else { /* 可答状态 */ }
} else {
    answerArea.style.display = 'none'
}

3. 计分与惩罚系统修复（P1）

3.1 惩罚阈值调整

轮次RISE（亲密惩罚）FALL（公开惩罚）理由
第1轮不触发不触发信息采集轮，不惩罚
第2轮≥ 60≤ 35当下匹配，适度触发
第3轮≥ 50≤ 40人性博弈，高频触发

3.2 AI 评分质量

  • 匹配分析 prompt 强化：要求每对必须有分数、必须拉开差距、至少一对超阈值
  • AI 返回校验：pairs 为空时重试一次，仍空则用兜底（随机 30-80 分）
  • 兜底逻辑从"暂不可用"改为生成模拟数据，保证游戏继续
